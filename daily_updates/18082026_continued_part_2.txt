## Mistakes

- Clarified multiple return values and unpacking.

## Interview Takeaways

• Function composition = chaining returned values through multiple functions.
• Multiple values can be returned and unpacked into separate variables.
• None in arithmetic can cause TypeError.
• Separate base and customer discounts because they are independent responsibilities.
• Prefer explicit parameters over hidden global dependencies.
• Configuration changes should ideally not require calculation-code changes.


- Pure functions are easier to test, reuse, and reason about.
- Separate configuration retrieval from stable calculation logic.
- Processing N independent orders generally requires O(N) work.
- Large-scale design requires thinking separately about algorithm structure, data volume, network, memory, and persistence.
- Database-backed configuration should not force unrelated calculation functions to change.
